# Instalación y operación (ES)

Esta copia no está conectada a ninguna cuenta. La instalación privada que originó el ejemplo no se copia ni se modifica. No habilite entregas hasta validar los destinatarios y autorizar un envío de prueba.

## Capas de verificación

1. **Pruebas locales:** `python3 -m venv .venv && .venv/bin/python -m pip install -e '.[test]'`; luego `PYTHONPATH=src .venv/bin/python -m pytest -q tests`. No accede a Gmail/Slack.
2. **Configuración y modelo:** copie `config/briefing.example.json` a `config/briefing.json`; configure `schedule.timezone` (IANA), hora y días, y `model.name` con un tag de `ollama list`. El ejemplo sugiere `qwen3:8b`, pero debe instalarlo (`ollama pull qwen3:8b`) o elegir uno realmente instalado. Ejecute `PYTHONPATH=src .venv/bin/python -m ai_daily_briefing.cli config/briefing.json`. El ejemplo de destinos no pasa la validación de envío; eso es intencional.
3. **Informe sin envío:** ejecute `PYTHONPATH=src .venv/bin/python scripts/run_once.py config/briefing.json --workdir var`. Se consultan fuentes públicas y Ollama y se registra una auditoría; sólo si hay piezas seleccionadas se generan HTML/PDF. Revise fechas, fuentes, clasificación y enlaces. Puede haber artefactos aunque la auditoría esté en estado `failed`: no equivalen a un informe apto para envío. Esta corrida sin `--deliver` no toca Gmail/Slack. Si falla una fuente, no convierta el fallo en «sin novedades»: bloquea el correo con el informe, aunque una corrida con salida autorizada puede publicar en Slack un estado de fallo.
4. **Conexiones:** cree una clave **de proyecto** Composio Platform en su dashboard; guárdela en el prompt oculto `python3 scripts/configure_project_key.py`. No pegue claves por chat, en argumentos, JSON o Git. Instale el extra `.[connect]` para `python3 scripts/connect_owner_accounts.py` con `send_enabled=false`; complete los enlaces OAuth de Gmail y Slack con sus propias cuentas. Configure `delivery.sender`, `recipient`, `slack_channel_id` y `slack_channel_name` (nombre real, sin `#`) en el JSON local. Compruebe el canal y la identidad remitente antes de cualquier envío. Esas conexiones de plataforma son distintas de otras sesiones personales de Composio.
5. **Prueba externa (requiere autorización):** sólo tras revisar los artefactos y el destino, habilite la compuerta local `delivery.send_enabled=true` y use `PYTHONPATH=src .venv/bin/python scripts/run_once.py config/briefing.json --workdir var --deliver` **una vez**. Esto envía el HTML en el cuerpo, adjunta el PDF y publica el estado en Slack. Si un resultado es incierto, inspeccione el libro de pendientes y Gmail Enviados/Slack; no repita a ciegas. Confirme la recepción en la cuenta destinataria; «Enviados» por sí solo no prueba llegada. Para volver al modo seguro, desactive `send_enabled`.
6. **Programación (autorización independiente):** con `send_enabled=false` cree el puente privado usando `.venv/bin/python scripts/create_bridge.py "$HERMES_HOME/scripts/ai_daily_briefing_dispatch.py"`. Defina `HERMES_HOME` para el perfil correcto si no está en el entorno. El generador no crea cron ni envía correo y se niega a sobrescribir un puente existente. **La expresión cron la interpreta el reloj/zona del host de Hermes, mientras que la entrada usa `schedule.timezone` del JSON.** Antes de activar, compruebe que ambos producen exactamente la misma próxima fecha y hora local; si no, ajuste la zona del host o convierta explícitamente la expresión para ese host (y revise cambios de horario estacional). No active un trabajo cuya próxima ejecución no coincida. Para un host en la misma zona que el JSON de ejemplo, cree pausado:

```bash
hermes cron create '30 9 * * 1-6' --name 'AI Daily Briefing' \
  --script ai_daily_briefing_dispatch.py --no-agent \
  --interpreter "$PWD/.venv/bin/python" --workdir "$PWD" --deliver local --paused
hermes cron list
```

Con la compuerta aún apagada, haga una previsualización segura: reanude sólo el ID del trabajo, lea `Next run` con `hermes cron list` y vuelva a pausarlo de inmediato. Compárelo con `schedule.next_runs` en la zona IANA del JSON (por ejemplo: `PYTHONPATH=src .venv/bin/python -c 'import json; from datetime import datetime; from zoneinfo import ZoneInfo; from ai_daily_briefing.schedule import next_runs; s=json.load(open("config/briefing.json"))["schedule"]; print(next_runs(s,datetime.now(ZoneInfo(s["timezone"]))))'`); **no habilite el envío si difieren**. Tras nueva autorización explícita y comprobaciones de conexiones, modelo, pendientes y horario, active `send_enabled=true`, valide de nuevo el JSON y reanude **sólo** el ID del trabajo propio con `hermes cron resume <ID>`; léalo de vuelta con `hermes cron list`. No ejecute `hermes cron run` como prueba: puede producir un correo adicional. La entrada sólo funciona dentro de los primeros 15 minutos del horario local y crea `var/scheduled-attempts/<fecha>.json` antes de cualquier salida. El marcador evita un segundo intento ese día aun si el resultado queda incierto. Un equipo apagado o suspendido puede perder la ventana; no hay envío retroactivo garantizado.

## Seguridad y límites

- Composio procesa correo y estados de Slack; supervise su propia cuota/condiciones. Ninguna fuente de búsqueda de pago está activada en el ejemplo. Tavily es opcional: confirme créditos, ausencia de cargos y calidad antes de habilitarlo.
- Sólo se confirma el PDF original si la copia de Gmail Enviados coincide en hash. Slack se coteja por timestamp y texto; la recepción del correo debe confirmarse por separado.
- HTML/PDF comparten los mismos datos, pero el PDF se renderiza de la misma representación, no por conversión de HTML byte a byte.
- El cliente HTTP restringe destinos, aunque eso no sustituye auditoría de seguridad integral. No publique archivos locales, reportes, tokens OAuth, identificadores de usuario o IDs de canal.
- Documentación de Hermes: https://hermes-agent.nousresearch.com/docs/user-guide/features/cron .
