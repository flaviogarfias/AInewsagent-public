# Setup and operation (EN)

This is a standalone example, **not** the original live deployment. It has no connected accounts, credentials, or delivery state. Nothing sends until the local gate and an explicit outbound command or scheduled job are enabled.

## Layered walkthrough

1. **Local tests:** `python3 -m venv .venv && .venv/bin/python -m pip install -e '.[test]'`; then `PYTHONPATH=src .venv/bin/python -m pytest -q tests`. Expected: tests pass without Gmail or Slack access.
2. **Configuration:** copy `config/briefing.example.json` to the Git-ignored `config/briefing.json`. Set an IANA timezone, schedule, and an actually installed Ollama tag (`ollama list`). The example uses `qwen3:8b`; install it with `ollama pull qwen3:8b` or select a local alternative. Run `PYTHONPATH=src .venv/bin/python -m ai_daily_briefing.cli config/briefing.json`. The example has deliberately invalid outbound targets and sending disabled.
3. **Dry run:** with Ollama running and public feeds reachable, execute `PYTHONPATH=src .venv/bin/python scripts/run_once.py config/briefing.json --workdir var`. Expected: an audit entry and, if eligible items exist, HTML/PDF in `var/artifacts/<run-id>/`; no email or Slack post. Review dates, direct links, summaries, and red/yellow/green labels. Artifacts can exist even when the audit status is `failed`. Source failures block report email delivery and are not equivalent to no new items; an authorized outbound run may still post a failure status to Slack.
4. **Connect accounts:** obtain your own Composio **Platform project** key, store it using the masked prompt `python3 scripts/configure_project_key.py`, and install `.[connect]` before running `python3 scripts/connect_owner_accounts.py` while `send_enabled=false`. Complete Gmail and Slack OAuth. Set your own sender, recipient, `slack_channel_id`, and `slack_channel_name` (without `#`) in the ignored JSON. Verify the sender and channel; personal MCP connections are not automatically available in a Platform project. Never commit or paste credentials into chat.
5. **One authorized delivery test:** after reviewing the report and recipients, enable `delivery.send_enabled=true` in your ignored JSON and execute `PYTHONPATH=src .venv/bin/python scripts/run_once.py config/briefing.json --workdir var --deliver` once. Expected: HTML email body plus original PDF attachment and a Slack status. Check Gmail Sent headers/body/PDF and Slack channel history, then confirm recipient-side arrival separately. An uncertain attempt must be reconciled before any retry. Turn the gate off again if scheduling is not authorized.
6. **Optional recurring job:** with sending off, generate a private Hermes bridge via `.venv/bin/python scripts/create_bridge.py "$HERMES_HOME/scripts/ai_daily_briefing_dispatch.py"` (set `HERMES_HOME` to the active profile home). The generator neither schedules nor sends. **Hermes interprets cron in the host scheduler's timezone, whereas the dispatch guard interprets `schedule.timezone` in the JSON.** Do not assume they match. For a host using the same zone as the example JSON, create a **paused** `no-agent` job:

```bash
hermes cron create '30 9 * * 1-6' --name 'AI Daily Briefing' \
  --script ai_daily_briefing_dispatch.py --no-agent \
  --interpreter "$PWD/.venv/bin/python" --workdir "$PWD" --deliver local --paused
hermes cron list
```

With the send gate still off, temporarily resume that exact job ID, inspect its `Next run` via `hermes cron list`, and immediately pause it again. Compare it with `schedule.next_runs` for the JSON's IANA timezone (the equivalent preview command is in the Spanish guide); if they differ, correct the host timezone or explicitly convert the cron expression (including daylight-saving changes). **Do not enable delivery while they differ.** After separate authorization, verify the connections, local model, pending ledger, and slot, enable `send_enabled=true`, validate the JSON again, resume the **exact** job ID, and read it back with `hermes cron list`. Do not run `hermes cron run` merely as a check: it can send an additional report. The entrypoint allows only the first 15 minutes of the local slot, writes an exclusive daily marker before outbound activity, and never blindly retries an uncertain delivery. A sleeping/offline machine may miss the slot.

## Scope and safety

Up to one eligible paper and one news item are kept even with a red rating; red signals lower editorial value, not the absence of news. Fetch reachability is not a fact-check. The local model may misclassify. HTML/PDF come from the same report data, but the PDF is not a byte-for-byte conversion of HTML. Tavily is optional and disabled; Exa and Brave have no active adapters. No paid search is assumed. An isolated Ubuntu 24.04 ARM64 VM passed 173 tests on the exported code with local Ollama `qwen3:4b`; a fresh full-feed no-send report produced artifacts but failed the source-health gate (one error; separate OpenAI-link diagnostic returned HTTP 403). A previous Linux run had zero source errors. Delivery from that VM was not tested. Review generated summaries against primary sources before enabling delivery. See [Hermes cron documentation](https://hermes-agent.nousresearch.com/docs/user-guide/features/cron).
